# Repository instructions

## Human-facing documentation

- Keep README focused on the project's purpose, requirements, installation, use, build, tests, and releases. Link detailed technical documentation instead of repeating it.
- Describe the current software and material limitations. Remove duplicated explanations and obsolete instructions when editing documentation.
- Never include LLM reasoning, scratch notes, prompt fragments, conversation transcripts, instructions addressed to an assistant, or narration of the agent's editing workflow in README, guides, or release notes.
- Document user and maintainer procedures only when needed to operate the project; omit the conversational history that led to them.
- Keep agent-specific instructions in AGENTS.md rather than human-facing documentation. State verification results factually and distinguish tested behavior from unverified assumptions.
